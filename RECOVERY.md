# Private operations and recovery

Keep `.env.local`, provider environment values and owner backups private. Windows file ACLs are inherited from the owner workspace; POSIX mode bits do not establish a Windows ACL. Keep the workstation account and backup medium controlled. Do not put secrets in the judge evidence pack.

Run `npm run backup` during a quiet maintenance window with no active issue/purge. It exports the private application tables in a repeatable-read snapshot, original/generated example objects and signed public checkpoints. Each object has a digest. If a concurrent purge removes an object, backup fails rather than claiming success; retry in a quiet window. Storage and database do not share one atomic snapshot. Preserve pending issuance reservations and staged objects if relevant. Verify backup completeness and retire old copies within 30 days. After a private-data deletion, retire affected older backup copies too.

Signing key configuration is deliberately **not** in the data backup. Back up it separately once; keep the public key ring including historical keys. Do not rotate silently during restoration. Independently retain a signed checkpoint on removable/offline storage and compare it with current exports using `audit:checkpoint`. A file writable by the same compromised owner is not a third-party witness.

Disposable restore: create/migrate an empty **separate** Supabase Free project within the two-project allowance. Set `RESTORE_DATABASE_URL`, `RESTORE_SUPABASE_URL`, `RESTORE_SUPABASE_SECRET_KEY`, `DISPOSABLE_RESTORE_PROJECT=true` locally. `npm run restore:check -- backups/FOLDER` refuses matching live credentials/origin or a non-empty target, verifies backup digests/checkpoints against the locally trusted public ring, restores DB and objects with no overwrites, then checks restored history/objects. Its actual hosted result is pending until a target is supplied. A failed disposable restore can leave partial data **only in that target**; inspect/retire that disposable project normally before repeating, never reset production.

Auth password/session data is not included. Actual disaster recovery requires privately reprovisioning users through supported Admin APIs and remapping membership user UUIDs; do not mistake imported old UUIDs for valid recovered Auth accounts. Restore the original signing configuration, choose the actual stable APP_ORIGIN intentionally and run doctor. Old certificates retain their signed original origin; keep that domain available or explain any migration limitations. Never regenerate original PDFs during recovery.

Forgotten operator password: `npm run operator:reset` prompts without echo and revokes refresh sessions via supported Admin APIs. Previously minted JWT access tokens can last until expiry. Disable the user’s issuer memberships first for immediate application denial. Owner backup and dashboard access are prerequisites for recovery; no public reset endpoint or secret-in-URL admin access is provided.

Pending purge: retry its approval from the authorised issuer inbox after resolving Storage failure. Downloads are already blocked while pending. Completion is recorded only after private payload/original removal and the signed purge event commit. Retained public signed evidence is deliberate and documented.

Abandoned issuance cleanup: `npm run maintenance:cleanup`, at most 50 old reservations per call with one-day grace, lease/reference checks and a persisted CLEANUP state. Deletion failures remain retryable. Do not kill unrelated machine processes or weaken security. Durable hosted state never uses the Vercel filesystem.
