# CertiProof

A fictional certificate registry with private issuer login, immutable PDFs, detached Ed25519 proof, a signed hash-linked ledger, browser-local file checking and a privacy request queue.

**Release status: not deployed yet. Hosted lifecycle, persistence, isolation and recovery gates need owner-configured Supabase/Vercel/GitHub accounts.** See ACCEPTANCE_REPORT.md and EXTERNAL_SETUP.md. Never use local UI checks as evidence that hosted data works.

## Windows setup

Use Node 24 LTS. A local Node 24.21.0 executable is installed in this workspace for checks. In PowerShell, set it for this terminal only:

```powershell
$env:PATH = "$PWD\node_modules\node\bin;" + $env:PATH
node --version
npm ci
npm run configure
npm run keys:generate
npm run setup
npm run doctor
npm run dev
```

The ordinary hosted demo requires internet, but does not need Docker or WSL. The first `npm ci` on another machine needs a separately installed Node 24 LTS because workspace dependencies do not exist until installation.

`configure` prompts for the public Supabase URL/publishable key, operator email and APP_ORIGIN. It asks for SUPABASE_SECRET_KEY and DIRECT_URL without echo. Obtain API keys from Supabase Project Settings → API; obtain the **session pooler** connection on port 5432 from Connect. Replace the password placeholder in the connection string privately (URL-encode special characters). Never paste credentials into chat.

`setup` applies versioned migrations using DIRECT_URL, provisions the restricted certiproof_runtime role, generates its password locally, derives a transaction-pooler DATABASE_URL on port 6543 and creates the private certificate-originals bucket and two fictional issuers. The operator chooses a password in a hidden prompt; account confirmation uses the supported Admin API rather than email delivery. Reruns preserve accounts, keys, existing roles/memberships and records. Check the derived host/port against dashboard Connect. `doctor` verifies that DATABASE_URL actually uses the restricted role.

The signing identity was generated once in gitignored `.env.local`; it is never generated by build/startup/deploy/seed. Back it up separately and privately. Historical trusted public keys must stay in the external configuration ring. Do not commit `.env.local`, backups, passwords or issuer credentials.

## Public deployment

1. Create a **private** personal GitHub Free repository and push this source. Configure Git identity locally if needed; do not publish secrets. Vercel Hobby is for eligible personal noncommercial projects.
2. Import only that repository in Vercel. Framework: Next.js. Node: 24.x. Install: `npm ci`. Build: `npm run build`. Select a nearby supported function region (default configuration uses bom1; change only if the provider/DB region calls for it).
3. Obtain the stable `https://…vercel.app` production domain. Set `APP_ORIGIN` to that origin in `.env.local` and Vercel Production environment. Configure Supabase Auth Site URL to it; allow only necessary exact redirects. This release uses password login and no OAuth callback.
4. Enter app environment values from `.env.local` in Vercel dashboard → Project Settings → Environment Variables. Public names: NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY. Everything else—especially DATABASE_URL, signing key, ABUSE_HASH_SECRET and SUPABASE_SECRET_KEY—stays server-only. DIRECT_URL is needed for owner migrations, not ordinary runtime. Do not run migrations/seed during a build.
5. Deploy publicly without Vercel authentication on the production domain. Keep issuer authentication and preview protection. Run `npm run doctor`, then `npm run demo:prepare` **after** the stable origin is fixed. Generate real fixtures through issuance/revocation services.
6. Set TEST_BASE_URL to the real production URL. Run `npm run deploy:check`, `npm run demo:check`, and authenticated browser checks. Redeploy once, then confirm IDs, signing key identity and downloaded original bytes persist. Record actual evidence and complete phone/network checks.

There is no production URL until the provider actually returns one. A static export is insufficient. No Vercel CLI is retained: GitHub import/dashboard deployment avoids an unnecessary vulnerable tooling chain. Authorised provider integrations can be used if supplied later.

For this workspace, the existing BytesBySuyash GitHub login was verified and is reused for the private repository; no repeat GitHub login is required. See EXTERNAL_SETUP.md for the resulting source URL/status. The independent Node executable `.tools/node24/node.exe` survives clean npm installations; it can run the configuration helper directly: `& '.\.tools\node24\node.exe' --import tsx scripts/configure.ts`.

## Normal use

- Public visitors: choose PDF/PNG/JPEG, type a full cp_ ID, or try/download a fictional example. Files remain local. Only IDs/digests reach the API.
- Issuer staff: sign in; select their issuer; preview and confirm fictional name/course/dates; download the stored original. A processing response requires retry with the same request.
- Admin: revoke with confirmation; inspect/export ledger proof; try the isolated integrity lab; review support/deletion requests. Deletion requires a private authority check and a recoverable purge.
- Platform admin: manage fictional issuers and scoped memberships. User accounts are privately provisioned through setup/Admin API, never public signup.

Original PDF match, record status, issuer status and proof checks are separate. Photos/QRs provide record-only results. Unknown documents cannot be authenticated here. No embedded Adobe/PAdES signature is claimed.

## Checks and management

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run start
npm run test:integration
npm run test:e2e
npm run check:release
npm run audit:ledger
npm run audit:checkpoint -- evidence-private/checkpoint-demo-aurora.json
npm run maintenance:cleanup
npm run backup
npm run restore:check -- backups/YOUR-SNAPSHOT-FOLDER
npm run operator:reset
```

Install Chromium once for browser checks: `$env:PLAYWRIGHT_BROWSERS_PATH="$PWD\.cache\ms-playwright"; npx playwright install chromium`. Tests run the built local app when TEST_BASE_URL is unset. For deployed tests, set TEST_BASE_URL; privately supply TEST_OPERATOR_EMAIL and TEST_OPERATOR_PASSWORD in `.env.local`. Test traces must stay private because they may contain operator sessions. Hosted tests are skipped when credentials are missing; a skip is not a pass.

Integration checks require a separate disposable Supabase project, its configuration in `.env.integration`, and DISPOSABLE_TEST_PROJECT=true. Do not point that file at production. Fault injection/restore/tampering belong only in isolated targets. Restore additionally requires RESTORE_DATABASE_URL, RESTORE_SUPABASE_URL, RESTORE_SUPABASE_SECRET_KEY and DISPOSABLE_RESTORE_PROJECT=true; the target must be empty and migrated. No live reset is provided.

Run cleanup daily during public operation. It removes expired counters, old resolved tickets and abandoned staging objects after a day with reference/lease checks; it never deletes committed originals. Pending approved purges can be retried from the inbox. Backups cover application records and original objects, not Auth passwords or private signing material. Reprovision Auth identities and remap memberships during actual recovery. Keep backups private, retire within 30 days and retire affected backups after authorised private-data removal.

Owner recovery resets the password and revokes refresh sessions through supported Auth APIs. Existing JWT access tokens can remain valid until configured expiry; disable the affected membership for immediate application denial. Configure an appropriate JWT expiry and test recovery.
